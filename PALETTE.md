# Ayu palette

This theme uses the official [ayu palette](https://github.com/ayu-theme/ayu-colors)
without any hand-picked colours.

## Source of truth

`tools/palette.json` is a verbatim copy of the values that ayu-colors generates
from `themes/light.yaml`, `themes/mirage.yaml` and `themes/dark.yaml`
(the same values that are published as the npm package `ayu`).

Everything else is derived from it:

| File | Role |
|---|---|
| `tools/palette.json` | the canonical token values (do not edit by hand) |
| `tools/gen-palette.mjs` | writes the `$ayu` map into the Sass sources |
| `tools/check-palette.mjs` | fails if a colour is not an ayu token |
| `tools/recolor-svg.mjs` | maps the artwork to the ayu colours |
| `tools/recolor-assets.mjs` | maps the rendered PNGs to the ayu colours |
| `tools/asset-map.json` | the artwork → ayu colour mapping |

The Sass sources contain a generated block:

```scss
// BEGIN AYU PALETTE (generated by tools/gen-palette.mjs from tools/palette.json)
$ayu: ( … ) !default;
// END AYU PALETTE
```

Never edit it by hand — run `node tools/gen-palette.mjs` after updating
`tools/palette.json`.

> `palette.svg` in the ayu-colors repository is a *picture* of the palette and
> is not a data source: it omits tokens such as `surface.sunk`. Use
> `themes/*.yaml` (or `tools/palette.json`) instead.

The same mapping is used by the GTK 2 `gtkrc` files, the Xfwm4 `themerc`
files, the Metacity themes, the Chrome/Chromium manifests and the libadwaita
overrides in `extra/libadwaita/`.

`ui.fg` is ayu's *muted* token. It is only used for secondary text
(entry placeholders, unfocused window buttons) and never as the foreground
of a filled surface: on `ui.panel.bg` it reaches just ~3:1, while
`editor.fg` keeps 6:1 (light) up to 9.5:1 (dark). The same rule applies to
the GNOME Shell top bar, where the clock, the panel labels and the status
icons all take their colour from `$panel_fg_color`.

## Derived colours

A few states have no ayu token. They are computed from ayu tokens with the
formulas below — never with a hand-picked hex value.

| Value | Formula |
|---|---|
| `$insensitive_fg_color` | `transparentize(editor.fg, .45)` light, `.55` dark |
| `$insensitive_bg_color` | `mix(surface.base, surface.lift, 40%)` light, `lighten(surface.base, 2%)` dark |
| `$header_bg_backdrop` | `lighten(surface.sunk, 3%)` light, `1.5%` dark |
| `$header_border` | `darken(surface.sunk, 7%)` |
| `$header_fg` | `saturate(transparentize(editor.fg, .2), 10%)` |
| `$panel_bg` | `darken(ui.panel.bg, 4.7%)` |
| `$button_bg` | `lighten(surface.base, 2%)` light, `lighten(surface.lift, 2%)` dark |
| `$selected_borders_color` | `darken(common.accent.tint, 20%)` |
| `$wm_button_close_hover_bg` | `lighten(syntax.markup, 10%)` |
| `$wm_button_close_active_bg` | `darken(syntax.markup, 12%)` |
| `$osd_button_bg` | `transparentize(lighten(ui.popup.bg, 22%), .6)` |
| `$osd_button_border` | `transparentize(darken(ui.popup.bg, 12%), .6)` |
| XFCE notification hover (GTK 2) | `shade(ui.panel.bg, 1.3)` (`#343C4D`) |

Pure black and white are only used for masks, shadows and gradients
(`rgba(0,0,0,.35)`, `white`, …); they are not brand colours.

## Assets

The sprite sheets and the vector artwork are Arc's; their *colours* are mapped
to the ayu palette by `tools/recolor-svg.mjs` (sources) and
`tools/recolor-assets.mjs` (rendered PNGs). The mapping lives in
`tools/asset-map.json`:

* accents: `#035BD6` (Ayu Light), `#E6B450` (Ayu Dark), `#FFCC66` (Ayu Mirage)
* window-button close states: the ayu red ramp
  (`#F07171`/`#F28886`/`#E5474F` light, `#F07178`/`#F39193`/`#EF616B` dark,
  `#F49F92`/`#F7B5AB`/`#F28779` mirage)
* widget chrome: the ayu surfaces and gray ramp

Antialiased edge pixels keep their original tone so the artwork is not
distorted; only the base colours of every asset are exact palette colours.

## Known deviations

* **Mirage shares the dark GTK assets.** The GTK 2/3/4 widget artwork is
  rendered once per variant: the light flavour uses the light accent, the dark
  *and* mirage flavours share the dark assets (`#E6B450`). The Xfwm4
  decorations do have a separate mirage set (`#FFCC66`).
* **Metacity ships a light and a dark theme only.** The mirage flavour
  installs the dark Metacity theme, whose colours are the dark flavour's
  official tokens.
* **Arc chrome shading.** The sprite sheets contain a few dozen neutral
  shades (gradients, bevels, shadows) that carry no brand colour. The flat
  colours of the artwork are ayu; the shading tones are Arc's.
* **`common.accent.on` has a low contrast ratio** on `common.accent.tint`
  (3.2:1 light, 4.4:1 mirage, 3.3:1 dark). This is the ayu palette's own
  pairing and is used for button labels and selected text.
